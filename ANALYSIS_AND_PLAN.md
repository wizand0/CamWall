# Анализ и доработка проекта CamWall

## Выполненные задачи:
1. Проведен анализ структуры проекта
2. Изучены все основные компоненты:
   - Модели данных (Camera, Frame)
   - Репозитории и DAO (Room database)
   - Use cases
   - ViewModel (CameraWallViewModel)
   - UI слой (Compose screens)
   - RTSP захват кадров (RtspFrameCapture)
   - Настройки приложения

3. Обнаружена проблема с Hilt - аннотации были удалены, но зависимости остались в build.gradle
4. Понятно, что текущая архитектура предполагает постоянное получение кадров из RTSP потоков, что является энерго- и ресурсоемким подходом

## Текущее состояние:
- Проект успешно собирается с небольшими изменениями
- Реализована базовая функциональность добавления камер
- Есть экраны для просмотра списка камер, добавления новых, деталей и настроек
- Реализован захват кадров из RTSP потока с помощью Media3 и ExoPlayer
- Используется Room для хранения информации о камерах
- Используется DataStore для хранения настроек

## Необходимые доработки:
1. Удалить оставшиеся зависимости Hilt из build.gradle
2. Заменить архитектуру на событийно-ориентированную систему получения кадров
3. Реализовать фоновое обновление кадров по расписанию или по требованию
4. Добавить оптимизацию энергопотребления
5. Реализовать кэширование кадров
6. Добавить обработку ошибок и состояния подключения камер
7. Реализовать систему оповещений о сбоях подключения
8. Добавить настройки интервалов обновления для разных камер
9. Реализовать очередь задач для фонового обновления кадров

## Новый подход к RTSP:
Вместо постоянного воспроизведения RTSP потоков:
- Хранить последний полученный кадр в кэше
- Обновлять кадры по расписанию или по требованию
- Использовать WorkManager для фоновых задач
- Реализовать логику "умного" обновления (учет активности, батареи, сети)
- Добавить возможность ручного обновления кадров
